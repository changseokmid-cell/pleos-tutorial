# 심사 안내: 제품에서 코드까지

먼저 README의 [기획 배경](../README.md#왜-이-앱이-필요한가)과 [튜토리얼 모드를 켠 뒤의 경험](../README.md#튜토리얼-모드를-켜면)을 읽어 보세요. SDV로 차량이 발전하는 동안 디지털 조작에 익숙하지 않은 초기 고객이 기능을 발견하고 익히는 과정을 어떻게 지원할지 설명합니다.

이어서 [다섯 영상](../README.md#다섯-가지-고객-경험)에서 관심 있는 장면을 골라 보세요. 각 썸네일 아래에서 **영상 → 장면 설명 → 관련 코드 → 검증 근거**로 이동할 수 있습니다. 전체 영상은 약 6분 21초이며, [기능별 상세 안내](../demos/README.md)는 영상의 목표 경험과 현재 APK에서 확인한 범위를 함께 설명합니다.

실제로 실행한 앱은 [서명 APK 녹화와 결과](../README.md#실제-apk-실행과-검증)에서 확인할 수 있습니다. 에르고는 revision-3, 사운드는 위치 중심 v5를 연결했으며, 기존 APK·시험 결과는 그대로 보존했습니다.

## 해결하려는 문제

차량에 기능이 있어도 이름·위치·효과를 모르면 자신의 불편을 해결하는 데 쓰기 어렵습니다. ‘내 차 사용 안내’는 Pleos 차량 안에서 사용자의 요청과 현재 차량 상태를 연결해, 기능을 짧게 체험하고 다시 사용하도록 돕습니다. 초기 고객 가설은 [작품 소개](proposal-public.md)에 정리했습니다. 연령별 미인지율이나 학습 효과를 이미 입증했다고 주장하지 않습니다.

## 대표 장면: 동승자만 춥다면

1. 사용자가 튜토리얼을 켜고 좌석별 독립 온도를 요청합니다.
2. P·차량 UX 허용, 동승석 착좌, 공조 전원·좌우 온도 등 최신 상태를 확인합니다.
3. ‘운전석 21°C를 유지하고 동승석을 24°C로 바꿀까요?’라고 제안합니다.
4. 수락 후 SDK 지원성을 확인하고 SYNC 해제를 요청합니다. 해제 결과를 다시 읽은 뒤 동승석 온도를 요청합니다.
5. 좌우 온도와 연동 상태를 재조회해 결과를 판단합니다. 명령 접수 ACK만으로 성공을 표시하지 않습니다.
6. 체감 응답은 차량 상태 확인과 구별해 이력에 남깁니다. 앱을 다시 열면 모드는 Off이고 이력·기능별 설정은 남습니다.

실제 제어는 [명령·재조회 로그](../evidence/release-smoke-verified/evidence.jsonl), 앱 재시작은 [전후 비교](../evidence/release-smoke-verified/run.json)에서 확인할 수 있습니다. 차량 상황은 에뮬레이터 콘솔로 만들었고 수락·체감 응답은 자동 UI 탭입니다.

## 자료를 보는 기준

| 자료 | 보여 주는 것 | 해석 범위 |
|---|---|---|
| 고객 경험 영화 | 고객 상황과 제품의 목표 경험 | 연출 장면이며 구현 완료 증거가 아님 |
| Release_Emulator.mp4 | 서명 APK의 제어·Off·재실행 | 무음 녹화, 자동 UI 입력 |
| APK와 Android 소스 | 현재 구현한 동작 | 시트·음장·SPREAD 전용 자동 제어 없음 |
| evidence의 JSON·화면 | SDK 관측, 세션, 재시작 비교 | 콘솔·ADB·SDK·자동 응답의 출처를 함께 읽음 |
| 단위 시험 | 안전 조건·값·의도 분류의 논리 | 실제 차량 실행의 대체 증거가 아님 |

## 코드에서 확인할 설계 판단

- 한 번에 한 체험만 진행하도록 Coordinator가 현재 세션을 관리합니다.
- 지원되지 않거나 오래된 값은 UNKNOWN/오류로 남깁니다. 빈 값이 false나 0으로 바뀌지 않습니다.
- SYNC 해제와 온도 변경 각각의 명령 접수 뒤 별도 재조회를 수행합니다.
- 차량 상태 확인과 ‘느꼈다’는 응답은 다른 기록입니다.
- 재시작 시 실행 중 세션은 재개하지 않고, 기능별 선택과 체험 기록을 보존합니다.

[구조와 함수별 안내](architecture.md) → [지원 범위](implementation.md) → [재현 절차·전체 결과](testing.md) 순서로 읽으면 이 판단을 실제 코드와 연결할 수 있습니다.

## 남은 검증

사람의 STT 발화·순정 Gleo 왕복은 사용자가 추후 시험하도록 정했습니다. 음성 반복 안정성, 전화·내비·미디어와의 충돌, 2시간 주행 후 제안, 실차 사양별 동작, 고객의 기능 발견·재사용은 후속 검증입니다. 이번 자료는 구현과 에뮬레이터 실행을 입증하며 사용자 연구 결과를 대신하지 않습니다.
